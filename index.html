Problem-led physical-systems research • coverage-first universe • September 2026

Frozen search thesis

Target a PhD in service of an important problem — primarily fusion, scaling compute through photonics/physical computing, or optical communications — where research includes some combination of physical modelling, inference, algorithms, experiments and implementation on real systems. Preserve and compound serious programming / optimization / HW–SW debugging capability rather than becoming analysis-only.

Four-axis fit test

Physics — real physical mechanisms matter.   Applied maths — modelling, inference, DSP, optimization, control or numerical methods.   Engineering — implementation, hardware/software, experiments, prototypes, real systems.   Slow horizon — the underlying problem can support years to decades of cumulative work.

Ideal loop: physical problem → model → simulate/infer → devise solution → implement → experiment/test → debug → refine.

This is not a prestige ranking. Priority A/B is a fit-investigation priority: which rows deserve deeper project/thesis/advisor diligence first. The purpose of this version is to be broad enough that subsequent work should mostly remove rows, not discover whole missing directions.

A Primary investigation pool
Problem + research depth + implementation/system loop appear especially aligned.
B Retain for project-level screening
Strong adjacent fit, but one dimension (physics, implementation, objective, or ownership) needs verification.
Implementation signal
“Strong” means the lab/ecosystem visibly supports building, control, testbeds, real-time systems, prototypes or experimental deployment. It is not yet a claim about every PhD project.
Destination-role lens: optical link architecture

MediaTek-style FEC-to-FEC optical systems: link physics + coherent/IM/DD + Tx/Rx + DSP/FEC + system model + measured-link correlation. First inspect the project in Zibar’s DTU group, Kahn’s Stanford group, Okonkwo’s TU/e lab and Chalmers FORCE (Karlsson/Andrekson). Oxenløwe is strong for a data-centre transmission project; Brès is more conditional because PHOSL often centers on nonlinear photonic subsystems.

AMD-style optical I/O: SerDes + package/electrical channel + optical engine + link/system co-design. Screen the Optical I/O / compute rows for electrical–photonic co-simulation, signal integrity, packaging and measured hardware. An optical transmission thesis alone does not establish package/SerDes experience.

For every project ask who owns the full-link model, what is measured, how disagreement is debugged, which architecture decisions follow, and whether substantive implementation work is available. These are target-role lenses, not claims that a new PhD graduate meets a tech-lead job description. References: DTU MLiPS · Stanford OCG · TU/e · Chalmers FORCE · EPFL PHOSL.

Computational physical systems / SciML: screening note

Preferred orientation: domain and physical model first, ML as a modelling and inference tool. For these rows, ask which physical system the student will study for years, what equations and measurements they own, why learning is needed, and what prediction, diagnosis or design decision improves. Current priority reflects fit-investigation, not prestige or a verified opening. Hardware deployment is optional for this pass.

How to prune this database

For every row, the next diligence pass should answer the same questions: (1) what important problem is the PhD serving; (2) what is genuinely unknown; (3) what did 2–3 recent students personally model/build/code/implement; (4) did their work touch a real system; (5) what concrete capability or understanding existed at thesis end; (6) is the PI technically deep and engaged enough to teach; (7) where did graduates go; and (8) does the project preserve transferable C/C++/DSP/optimization/systems capability?

Important: admissions/opening links are starting points, not claims that a funded opening exists today. European PhDs are often vacancy/project based; US programs often admit through a department. Current opening status should be checked separately during the next pass.
