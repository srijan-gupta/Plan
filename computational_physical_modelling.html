Computational physical modelling & simulation

A top-level career/research direction independent of any one physical domain. The durable craft is to learn a physical system deeply enough to turn it into a trustworthy computational experiment, make that experiment computationally capable, confront it with reality, and use failures to improve the physics.

physical phenomenon → governing physics → mathematical model → numerical method → simulator implementation → HPC / performance optimization → simulation → experiment / observation → discrepancy / mechanism → refinement

Why this direction survived

It unifies recurring preferences that appeared before any particular PhD posting: understand the system rather than operate it; model it; simulate it; compare prediction with reality; debug the mismatch; refine; repeat. Simulator-building and performance work are attractive parts of the scientific process, not merely infrastructure.

Decades-scale identity

Computational physicist / physical-systems modeller. Repeatedly become deep in new physics while accumulating a reusable mathematical, numerical and HPC language. The physical domain can evolve; the craft compounds rather than resets.

Hard distinction

Not generic HPC support. A strong group gives the researcher ownership of the physical question and/or mathematical/numerical model as well as meaningful simulator implementation. Merely porting, benchmarking or launching an existing code is insufficient.
