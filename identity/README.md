## Standing maintenance protocol

When a Field discussion changes identity, motivation, work structure or a durable decision criterion:

1. Read the current model's constitution, navigation state and relevant dimension.
2. Record the observation with its date/source. Distinguish user statements, demonstrated behaviour and assistant interpretations.
3. Classify each change as new observation, new identity discovery, strengthened evidence, framework refinement, hypothesis update or architecture change.
4. Update affected dimensions, confidence, competing explanations, hypotheses and open questions together. Preserve why a conclusion changed.
5. Update the operational research filter only if the evidence warrants it. Keep methods and current opportunities subordinate to identity and meaningful problems.
6. Check relative links, contradictions and traceability. Commit and push the relevant files, then provide the commit link or explicitly flag failure.

Do not promote a career hypothesis to identity, infer student ownership from prestige, or replace stable criteria with the latest enthusiasm. Missing evidence remains unknown. Do not add sensitive personal details merely because they are available; this repository is public.

This protocol governs future authorized Field updates when this repository is used. It is not a background sync service or an automatic update schedule.

The full evidence log and standing directives are embedded in the canonical document. Update that document first; regenerate the companion evidence reading copy from it. Preserve prior evidence entries and append corrections with dates. Record historical coverage limits; never label an update exhaustive without a source-by-source coverage audit.
